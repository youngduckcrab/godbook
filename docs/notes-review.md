# 출처 메모 독립 검토

강의 하나를 마치면 그 강의의 모든 항목의 출처 위치(`loc`)와 출처 메모(`note`)만 독립된 검토자가 본다(사용자 결정, 2026-11-20). 본문의 독립 검토는 두지 않는다는 결정은 그대로다.

까닭: 메모는 건수가 많아 작성자의 자기 검토와 지휘자의 표본 검사로는 걸러지지 않는다. 위상수학 입문 67개 항목에서 이 검토가 찾은 것은 틀린 위치 약 31, 출처의 말을 틀리게 옮긴 것 12, 틀렸거나 근거가 모자란 "출처에 없다/이 항목이 덧붙였다" 6, 본문에 없는 블록 제목을 가리키는 메모 10, 빠진 겹침 약 100 이었다.

이 문서는 그 검토자의 설명서다. 검토자는 이 문서와 docs/reviewing.md, docs/conventions.md 의 "출처" 절, docs/self-review.md 의 3절, docs/writing.md 의 출처 메모 부분을 읽는다. 글과 보고는 한국어로 쓴다. **작성자의 자기 검토 기록은 읽지 않는다**(같은 눈으로 다시 보지 않기 위해서다).

## 대상
맡은 단원의 단원 파일(content/courses/<강의>/NN-*.md)의 concepts 에 든 모든 항목의 머리말 `sources:` (ref, loc, note). **본문(진술, 증명, 예, 직관)은 검토 대상이 아니다.** 다만 메모가 본문의 블록(예시·반례·확인 질문의 제목, 번호)을 가리키므로 본문을 열어 대조한다.

## 출처 텍스트
지시문이 출처마다 텍스트의 경로와 쪽수 대응(인쇄 쪽 = PDF 쪽 − N)을 준다. 줄바꿈에 걸린 문장은 `node scripts/source-grep.mjs <출처.txt> <N> "<정규식>" [앞뒤 글자 수]` 로 찾는다(줄 번호와 인쇄 쪽을 준다). 쪽은 `awk '{n=gsub(//,""); pg+=n} NR==<줄> {print pg+1-<N>}' <출처.txt>` 로 다시 센다. 수식이 깨져 보이면 PDF 의 그 쪽을 그림으로 본다. 쪽수가 없는 출처(LaTeX 원본 등)는 `grep -n` 으로 줄을 확인한다.

## 주장마다 할 일 (메모의 문장 하나하나)
1. **위치(loc 과 메모 안의 번호·줄·쪽)**: 그 자리를 실제로 열어 그 번호의 진술이 메모가 말하는 그 진술인지 본다. 번호가 놓인 절 번호도 원문에서 확인한다(다른 절 아래 적은 것이 가장 흔하다). 쪽은 폼피드로 다시 센다. 줄 범위로 적은 위치는 그 환경(정의·명제·증명)의 시작과 끝과 맞는지 본다.
2. **출처가 무엇을 말한다/증명한다/증명 없이 적는다/연습문제로 둔다**: 그 문장을 원문에서 찾아 대조한다. "증명하지 않는다", "~라고만 적는다"는 그 환경과 앞뒤를 끝까지 읽고 판정한다.
3. **부정 주장("출처에 없다", "나오지 않는다", "찾지 못했다", "이 사이트가 쓴 것/둔 것/붙였다")**:
   - 예시·반례·확인 질문에 대한 부정 주장은 **규칙 위반**이다(2026-11-19 규칙). 지운다. 겹침을 찾았으면 겹침으로 바꿔 적는다.
   - 정리의 진술·용어·증명에 대한 부정 주장은 검색어를 **표현을 바꿔 셋 이상**(기호 꼴, 영어 낱말 꼴, 대상 이름) 두 출처 전체에 써 보고, 그 장의 연습문제를 처음부터 끝까지 읽은 뒤에만 남긴다. 하나라도 나오면 사실대로 고친다.
4. **겹침의 누락**: 항목의 예시·반례·확인 질문·진술의 예가 다루는 **대상의 이름**(ℤ₆, U(8), ℚ, {1/n}, 이산 거리 같은 것)으로 두 출처 전체(연습문제 포함)를 검색해 나온 곳을 모두 읽고, 같은 대상·같은 결론·같은 발상인데 메모에 없는 것을 찾는다. 찾으면 "예시 '…'은 출처 …(위치)와 같은 대상이다/같은 발상이다" 꼴로 더한다.
5. **평가 말투**: 출처를 평가하는 말("틀렸다", "말없이", "엉성하다")은 사실 서술로 바꾼다("출처는 …라고 적는다. 이 항목은 …로 진술한다").
6. **메모가 가리키는 본문**: 메모가 "(3)은 …", "예시 '…'"라고 가리키는 번호·제목이 본문에 실제로 그렇게 있는지 본다(제목이 바뀌었는데 메모가 옛 제목을 가리키는 것 포함).

## 고치기
- 틀린 것은 **직접 고친다. 고칠 수 있는 것은 `sources:` 의 loc 과 note 뿐이다.** 그 밖의 줄(본문, requires, status, review_note 등)은 한 글자도 바꾸지 않는다. 끝에 `git diff -U0 -- <맡은 파일들>` 로 바뀐 줄이 모두 `    loc:` 또는 `    note:` 줄인지 확인하고 보고에 적는다.
- note 는 YAML 한 줄 문자열이다. 따옴표와 역슬래시를 깨뜨리지 않는다. 고친 뒤 `npm run check` 가 통과하는지 본다(다른 검토자가 동시에 다른 파일을 고친다. 자기 파일이 아닌 오류는 보고에만 적는다).
- 본문에서 틀린 것을 보면 고치지 말고 보고에 "본문에서 본 문제"로 적는다(파일, 줄, 무엇이 왜 틀렸는지).
- 커밋하지 않는다.

## 기록과 보고
기록 파일(지시문이 정한 경로)에 항목마다 표를 쓴다: | 메모의 주장 | 종류(위치/출처의 말/부정/겹침) | 한 행동(연 줄·쪽, 검색어와 건수) | 판정(맞음/고침/지움/더함) |. "확인했다"만 적지 않는다.
보고에는: 항목 수, 고친 건수를 종류별로(틀린 위치, 틀린 "출처의 말", 지운 부정 주장, 틀려서 고친 부정 주장, 새로 더한 겹침, 평가 말투), 대표 예 몇 개, 남긴 부정 주장의 목록과 근거, 본문에서 본 문제, git diff 확인 결과, npm run check 결과.
