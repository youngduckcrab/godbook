# 자기 검토 절차

작성자가 초안을 다 쓴 뒤 검토자가 되어 따라 하는 절차다. 지금은 독립 검토자를 두지 않는다(사용자 결정, 2026-11-19). 무엇을 오류로 보는지(여섯 가지 관점, ERROR·WARN·NIT 의 기준)는 `docs/reviewing.md`가, 글쓰기 규칙과 "검토에서 자주 나온 지적"은 `docs/writing.md`가, 표기와 받아들인 사실은 `docs/conventions.md`가 정한다. 이 문서는 그 기준을 **혼자서 어떤 행동으로 확인하는가**만 적는다.

## 1. 왜 따로 하는가

해석학 1~8단원과 선형대수 4~8단원은 작성자가 자기 검토를 한 뒤 독립 검토자가 다시 보았다. 그 보고서 28개에서 ERROR·WARN 이 약 100건 더 나왔다. 증명 본체의 수학 오류는 한 건도 없었다. 남은 것은 다음 네 무리다.

| 무리 | 대략 | 글쓴이가 놓친 까닭 |
|---|---|---|
| note 의 출처 주장("출처에 없다", "새로 만들었다", "이 사이트가 덧붙였다", "~라고만 적는다", "처음") | 40 | 해당 절과 그 연습문제만 찾았다. 다른 장, 줄바꿈에 걸린 낱말, 수식으로만 적힌 것은 검색에 걸리지 않았다. 수가 다르면 다른 예라고 보았다 |
| 설명 글(직관, 반례·예시 제목, 힌트, 단원 글)의 일반 문장 | 25 | 문장이 말하는 변수만 바꿔 보고, 문장에 드러나지 않은 매개변수(첫째 항, 0 인 공비, 첫 피벗 앞의 열)는 넣어 보지 않았다. 고친 문장을 다시 대입하지 않았다 |
| 근거와 이름(이름 없는 작은 사실, requires, 같은 글자·이름표의 두 뜻) | 20 | 당연해서 근거를 달 생각을 못 했다. 한 항목 안에서는 겹치지 않아 다른 항목과 함께 읽을 때만 드러났다 |
| 뒤 항목이 쓸 진술의 부족, 상태가 바뀌면 거짓이 되는 문장 | 10 | 지금 항목만 보고 썼다. 뒤 항목이나 후반부가 붙은 뒤의 모습을 그려 보지 않았다 |

자기 검토는 목록을 받아 하나씩 따진 것(수치, 근거 번호, requires, "깨진다" → "깨질 수 있다")은 잘 잡았고, "확인한다"로만 적힌 것은 놓쳤다. 그래서 이 문서는 확인을 **목록을 만들고 그 줄마다 정해진 행동을 하는 것**으로 적는다.

## 2. 원칙

1. **쓴 직후의 확신을 믿지 않는다.** "이미 봤다", "맞다고 기억한다"는 근거가 아니다. 이번 검토에서 다시 한 계산, 다시 연 파일, 다시 친 검색어만 근거로 친다.
2. **읽지 말고 다시 한다.** 문장을 읽고 고개를 끄덕이지 않는다. 값을 대입하고, 식을 전개하고, 인용한 진술을 열어 나란히 놓고, 출처를 검색한다.
3. **쓴 순서와 다른 순서로, 종류별로 가로질러 본다.** 진술 → 출처 → 증명 → 설명 글 → 예시 → 이름 → 단원 글 순서로, 모든 항목의 같은 종류를 한꺼번에 본다(모든 반례 제목을 한 표에, 모든 note 를 한 표에). 한 항목을 처음부터 끝까지 읽으면 쓸 때의 흐름을 따라가 같은 곳에서 같은 것을 놓친다.
4. **검토 전에 초안을 복사해 둔다.** `mkdir -p <스크래치패드>/draft && cp <내 파일들> <스크래치패드>/draft/`. 고친 곳은 5절대로 이 사본과 비교해 다시 확인한다.
5. **주장을 확인한 범위로 줄인다.** 대입해 보지 못한 일반화, 다 찾지 못한 "출처에 없다"는 지우거나 좁힌다. "(검색한 범위)"는 검색어와 범위를 기록에 남겼을 때만 붙인다.
6. **남이 준 문구도 검토한다.** 지휘자 결정이나 출처 요약에 있는 문구, 이 문서의 예를 그대로 넣기 전에 같은 대입과 검색을 한다. 5단원에서 검토자가 제안한 반례 제목이 같은 이유로 다시 틀렸고, 출처 요약이 "출처에 없다"고 한 것이 출처에 있었던 일도 있다.

## 3. 준비: 목록 뽑기

검토의 재료를 기계로 뽑아 기록 파일에 붙인다. `F` 는 이번에 쓰거나 고친 파일 전부다.

```
F="content/concepts/<분야>/<id1>.md content/concepts/<분야>/<id2>.md content/courses/<강의>/NN-이름.md"
# (가) 일반 문장 후보: 블록 제목과 일반화의 말
grep -n -E '^:::(counterexample|example|remark|check|hint)' $F
grep -n -E '모든|항상|언제나|뿐|만 |반드시|매번|않는다|없다|깨진다|아니다|군데|까닭|때문|처음|마지막' $F
# (나) 출처에 관한 주장
grep -n -E '출처(는|에|의)|새로 (만들|골랐)|덧붙|이 사이트(가|의)|라고만|쓰지 않았|처음' $F
# (다) 인용한 번호
grep -o -E '\[\[[a-z0-9-]+(\|[^]]*)?\]\]의 \([0-9]+\)|\([A-Z][0-9]+\)' $F | sort | uniq -c
# (라) 출처 텍스트의 줄을 이은 판: 줄바꿈에 걸린 낱말을 찾는 데 쓴다
perl -0pe 's/-\n(?=[a-z])//g; s/\s+/ /g' <출처.txt> > <스크래치패드>/joined.txt
grep -o -i -E '.{60}basic variables.{60}' <스크래치패드>/joined.txt
```

줄을 이은 검색과 쪽 확인은 `node scripts/source-grep.mjs <출처.txt> <N> <검색어>` 로 한 번에 할 수 있다(줄바꿈·하이픈에 걸린 낱말까지 찾고, 원문의 줄 번호와 폼피드로 센 인쇄 쪽을 함께 보여 준다. N = PDF 쪽 − 인쇄 쪽). "출처에 없다"고 쓰기 전에 영어 낱말을 바꿔 가며 이것으로 책 전체를 찾고, 친 검색어와 건수를 기록에 남긴다.

**검색어는 주장 하나에 셋 이상.** 같은 내용을 가리키는 영어 표현을 바꿔 가며 찾는다(예: "real numbers under addition" 만 찾으면 0건이지만 "additive group of real", "(R, +)" 로는 6건이 나왔다. "S_n is nonabelian" 은 연습문제에 있었다). 기호로만 적힌 것, 연습문제, 뒤쪽 장의 증명 안을 따로 본다. 추상대수 1단원에서 지휘자의 표본 검사에 걸린 두 건이 모두 검색어 한두 개로 "찾지 못했다"고 쓴 경우였고, 다시 찾으니 17개 가운데 3개가 틀렸다.

**그 장의 연습문제는 검색하지 말고 처음부터 끝까지 읽는다.** 말로 된 물음("a ∼ b if φ(a) = φ(b) … describe the equivalence classes")은 기호 검색(g1−1 g2)에서 빠진다. 진술마다 "이 장의 연습문제 가운데 같은 것을 묻는 것"을 번호로 대조해 기록에 남긴다.

grep 은 후보를 줄일 뿐이다. 직관·반례·힌트·단원 글은 문단 단위로 다시 읽어 일반 문장을 빠짐없이 4.4 의 표에 옮긴다. joined.txt 에서 찾은 곳의 줄 번호와 쪽은 그 둘레의 낱말로 원본을 다시 grep 해서 얻는다.

## 4. 단계별 절차

### 4.1 진술

- **한다**: 진술마다 변수, 한정 기호, 가정을 적고 끝의 경우(공집합, 0, 1, 원소 하나, 크기 1, 빈 열, 등호, 끝점, 상수, 지수 0)를 넣는다. 정의가 "정확히 ~일 때"인지, 진술에 쓴 낱말이 모두 정의되어 있는지 본다.
- **방법**: 끝의 경우마다 가정과 결론을 한 줄씩 계산해 기록한다. "하나씩 정해져 있으면"처럼 무엇을 허락하는지 열려 있는 낱말은, 그 낱말로 정당화될 수 있는 가장 넓은 일(예: 각 n 마다 하나씩 고르기)을 적어 보고 진술이 그것을 막는지 본다.
- **고친다**: 거짓이 되는 경우, 한 방향뿐인 정의, 뜻이 열린 낱말이 나오면.

**(C) 뒤 항목을 지금의 진술로 쓸 수 있는가.** 이 단원 후반부와 다음 단원에서 이 항목을 인용할 후보를 출처의 다음 절과 출처 요약에서 셋 이상 적는다. 후보마다 증명 경로를 서너 줄로 적고, 단계마다 "어느 항목의 어느 번호인가"를 단다. 번호를 달 수 없는 단계가 모자란 진술이다. 정의는 뒤에서 쓸 **꼴**까지 본다(λ 를 밝힌 꼴만 정의하면 "고유벡터로 된 기저"를 쓸 수 없다). 이 단원의 증명 안이나 반례 안에서만 보인 사실 가운데 뒤에서 쓸 것도 찾는다. 모자란 것은 진술에 올릴지 지휘자에게 묻는다(7절).

### 4.2 출처 (note 와 loc)

자기 검토가 가장 많이 놓친 곳이다. 블록 하나에 한 줄씩 확인한다.

- **한다**: 예시, 반례, 확인 질문, 참고 블록, "출처에 명제로 없다"고 적은 성질마다 표를 만든다: `블록 | 핵심 대상(구체적인 수열·함수·행렬·집합) | 핵심 결론 | 출처에서 찾은 곳, 또는 검색어와 읽은 범위 | note 에 적을 말`.
- **방법**:
  1. 핵심 대상과 핵심 결론을 **영어 낱말, 수식의 꼴, joined.txt** 세 가지로 검색한다. 원문에서 "basic / variables"로 줄이 갈린 말은 한 줄 검색에 걸리지 않았고, 대각행렬의 거듭제곱처럼 식으로만 적힌 것은 낱말 검색에 걸리지 않았다(`diag`, `^N`, `1/n`, `(-1)` 같은 기호로도 찾는다).
  2. 범위는 **책 전체**다. 해당 절의 본문과 연습문제 전부, 앞뒤 절의 예, 같은 대상이 나올 만한 뒤 장의 증명과 1장 첫머리의 정의까지 본다. 놓친 것의 절반 이상이 다른 절이나 다른 장에 있었다.
  3. **발상으로** 비교한다. 수만 바꾼 것(성분 8 → 2, "F⁴ 의 벡터 다섯 개" → "3 × 5 행렬의 열"), 상수만 다른 것(1 + 1/n 과 2 + 1/n), 출처의 예를 일반화한 것(구간 (0, 1) → 일반 구간), 같은 함수를 제한한 것(ℝ 위의 x → (0, 1) 위의 x), 출처 증명 안의 수열에 값을 넣은 것(n/(1+ε)ⁿ 의 ε = 1)은 모두 같은 발상이다. "같은 대상에서 같은 결론을 같은 방법으로 보이는가"를 묻는다.
  4. 출처 요약의 "없다"를 근거로 삼지 않는다.
- **고친다**: 표의 줄마다 note 에 "출처 p.○ 의 ○○와 같은 발상이다", "출처는 연습문제 ○○로 둔다", "출처의 Example ○○를 명제로 올렸다", "출처에 없다(검색어 …, 범위 …)" 가운데 하나를 적는다. "예시와 반례와 확인 질문은 새로 만들었다"처럼 여러 블록을 한 문장으로 덮지 않는다. 한 블록만 겹쳐도 문장 전체가 틀린다.
- **부정·최초 주장**("출처는 ~라고만 적는다", "~는 쓰지 않았다", "처음 쓰는 곳은", "이 이름은 이 사이트가 붙였다", "출처는 a < b 를 적지 않는다")은 같은 방법으로 확인한다. 확인하지 못하면 "출처는 p.○ 에서 ~라고 적는다"처럼 본 것만 긍정문으로 쓴다.
- **쪽**: 쪽수는 폼피드로 센다. `awk '{n=gsub(/\f/,""); pg+=n} NR==<줄> {print pg+1-<N>}' <출처.txt>` (N 은 `docs/conventions.md` 의 출처 표). 쪽 머리글이나 기억으로 정하지 않는다.
- **수식**: 출처의 식을 따옴표로 옮기거나 출처가 무엇을 진술하는지 적을 때는 텍스트 추출을 믿지 않는다. `pdftoppm -f <쪽> -l <쪽> -r 80 -png <출처.pdf> <새 폴더>/p` 로 그 쪽을 그림으로 만들어 Read 로 열고 대조한다. 추출에서 절댓값 막대가 빠진 식을 그대로 옮긴 일이 있었다.

### 4.3 증명과 인용

- **한다**: 3절 (다)의 인용 목록을 줄마다 확인한다.
- **방법**: 인용한 항목 파일의 `:::statement` 를 열어 그 번호의 내용을 한 줄로 요약해 적고, 증명이 쓰는 꼴(가정, 첨자의 범위, 등호)과 나란히 놓는다. 예: "(6)의 (ii)는 0 < a < b 만 말한다 — 여기서는 n = 1 의 등호도 필요하다". 이어서 증명, 예시, 확인 질문의 모든 문장 끝에 "(무엇에 의해)"를 붙여 본다. 붙일 수 없는 문장이 이름 없이 쓴 작은 사실이다. 귀납은 0, 1, 2 를 넣어 기초 단계와 귀납 단계를 실제로 돌린다.
- **고친다**: 근거를 달고 그 항목을 requires 에 넣는다(예시에서만 써도 넣는다). 다른 항목의 예시·반례·직관·증명 단계에 기대는 곳은 그 자리에서 보이고, 뒤에서도 쓸 것이면 4.1 (C)로 넘긴다.

### 4.4 설명 글의 일반 문장

- **한다**: 직관, 반례·예시의 제목, 힌트, 참고 블록, 단원 글의 일반 문장을 모두 표로 옮긴다: `문장 | 문장이 말하는 대상 | 그 대상의 모든 매개변수 | 넣어 본 값 | 참·거짓`.
- **방법**: 문장에 나온 변수만이 아니라 **대상이 가진 모든 매개변수**에 끝값을 넣는다. 등비급수라면 공비만이 아니라 첫째 항 0, 공비 0, 1, −1. 행렬이라면 영행렬, 단위행렬, γI. 함수라면 상수함수, 미분계수가 0 인 함수, 끝점에서의 값. 부등식이라면 등호와 지수 0. 비유라면 비유의 각 부분이 정의의 어느 한정 기호에 해당하는지 적는다("어떤 높이의 천장이든"은 "하나라도"를 "아무 것이나"로 바꿔 말했다).
- 반례 제목이나 직관이 "○○이면 성립하지 않는다", "○○는 하나로 정해지지 않는다"이면 **○○이면서 성립하는 예를 직접 찾아본다**. 찾으면 그 문장은 거짓이다.
- **고친다**: 거짓이 되는 값이 하나라도 있으면 보인 예로 좁히거나("첫째 항이 1 이고 공비가 2 이면"), "~일 수 있다"로 바꾸거나, 빠진 조건을 넣는다. 고친 문장을 다시 이 표에 넣는다.

**가정이 쓰이는 곳과 까닭.** 직관이 "이 가정은 ~에서 쓰인다", "(3)은 (1)과 (2)를 합친 것", "~하는 까닭은", "이름은 ~에서 왔다"고 말하면 따로 표를 만든다: `문장 | 증명에서 그 가정을 쓰는 줄(모두) | 반례가 실제로 깨뜨리는 조건 | 뒷받침하는 증명·출처`. 증명을 위에서부터 읽으며 가정마다 쓰인 줄을 빠짐없이 찾고, 직관이 가리키는 반례가 바로 그 가정을 깨뜨리는지 본다. 까닭과 유래는 증명이나 출처가 실제로 말할 때만 남긴다.

### 4.5 예시·반례·확인 질문

- 수치는 처음부터 다시 계산한다. 항등식은 전개하고, 행렬 곱은 성분마다, 부등식은 양변에 수를 넣는다. 다시 한 계산을 기록에 적는다.
- 예시의 근거도 증명과 같은 엄격함으로 단다(4.3 의 "(무엇에 의해)"). 확인 질문이 본문의 예시·반례를 다시 묻지 않는지, 출처 연습문제와 겹치는지는 4.2 의 표에서 함께 본다.

### 4.6 이름표와 기호

- **한다**: 이번에 붙인 이름을 목록으로 만든다. 굵게 정의한 말, 성질의 이름표("(c 가까이에서 유계)"), 경우의 이름 (가)·(나)·(ㄱ), 식의 이름, 함수·행렬·집합의 글자.
- **방법**: 각각 `grep -rn '<이름>' content/ docs/conventions.md` 로 다른 뜻으로 쓰인 곳을 찾는다. 이미 정의된 용어와 글자까지 같은가, 한 증명 안에서 (가)–(라)가 두 목록을 가리키지 않는가, 한 식에 소문자 함수 u 와 행렬 U 의 성분 u_{j,k} 가 함께 나오지 않는가, 막대·괄호 같은 기호가 다른 강의에서 다른 뜻인가(|f| 와 |A|, 번호 (1) 과 1 × 1 행렬)를 본다.
- **고친다**: 이쪽의 글자나 이름을 바꾼다. 통과한 항목과 겹쳐 바꿀 수 없으면 지휘자에게 묻는다.

### 4.7 단원 글과 강의 index

- 출처의 증명 방법을 말하는 문장("출처는 이 정리들을 ○○으로 증명한다")은 정리마다 출처를 열어 확인한다.
- **상태에 기대는 문장**을 찾는다: "마지막 두 항목", "지금 읽을 수 있는 것은", "작성 예정인 단원", "이 단원은 ○○만 쓴다", "○단원은 쓰지 않는다". 후반부가 붙은 뒤, 이 단원이 병합된 뒤, `planned_units` 가 빈 뒤에도 참인지 본다. requires 에 관한 주장은 `grep -h '^requires' <단원의 항목 파일들>` 로 확인한다.
- 뒤 단원과 아직 없는 항목의 예고를 지운다(진술 안의 "뒤 단원에서 따로 다룬다"도).

### 4.8 기계 확인과 화면

- `npm run check` 경고 0. 자기 파일이 아닌 경고는 보고에 적는다.
- `npm run build` 뒤 `grep -l 'katex-error\|\[\[' dist/c/<id>/index.html` 이 비어 있는지 본다.
- 이 사이트에서 처음 쓰는 표기(새 KaTeX 명령, 긴 식, 번호가 끊기는 목록, 제목의 괄호)가 있으면 화면을 직접 본다. `npx astro preview --port 4321 &` 뒤 `node scripts/render-check.cjs` 를 돌리거나 Playwright 로 1000px 과 390px 스크린숏을 찍어 Read 로 연다. katex-error 가 없어도 화면에서 틀리게 보인 일이 있었다(`\tag` 의 꼬리표가 식 바로 뒤에 붙어 곱으로 읽혔다).

## 5. 고친 뒤의 재확인

1. `git diff --no-index --word-diff <스크래치패드>/draft/<파일> <파일>` 로 바뀐 문장을 모두 뽑는다.
2. 바뀐 문장마다 그 문장이 속한 단계의 확인을 처음부터 다시 한다. 일반 문장은 4.4 의 표에, note 는 4.2 의 표에 다시 넣는다. "|r| < 1 이 아니면 합이 아니다"를 "공비가 2 이면 합이 아니다"로 고쳤는데 둘 다 첫째 항 0 에서 거짓이었다.
3. 한 곳에서 찾은 종류는 이번에 쓴 모든 파일에서 grep 으로 다시 찾고 검색어를 기록한다. 한 파일에서 고친 "1 ≤ n"(이름 없는 (Z1))이 뒤에 쓴 같은 단원의 두 파일에서 다시 나왔다.
4. 진술을 고쳤으면 `:::english`, `summary`, note 를 맞추고, 그 진술을 인용하는 다른 항목의 증명을 다시 본다.
5. 4.8 을 다시 돌린다.

## 6. 놓치기 쉬운 것 (실제로 있었던 예)

| 예 하나에서 넘겨짚은 일반화 | `rolle-theorem`, `mean-value-theorem` 반례 제목 "꺾인 점이 있으면 성립하지 않는다": \|x\| − x² 는 꺾인 점이 있어도 결론이 성립한다. `rank-nullity-theorem` "더해서 나오는 것은 공역의 차원이 아니다": dim V = dim W 이면 같다. `diagonalizable` "D 는 하나로 정해지지 않는다": A = I 이면 정해진다 | 조건을 만족하면서 결론이 성립하는 예를 찾았다 |
| 드러나지 않은 매개변수의 경계 | `geometric-series` 반례 제목, `terms-of-convergent-series-tend-to-zero` 직관, 5단원 글의 "공비의 절댓값이 1 이상이면 발산": 첫째 항이 0 이면 거짓. `ratio-test-for-series` "이웃한 두 항의 비가 언제나 r": a = 0 이나 r = 0 이면 비가 정해지지 않는다 | 첫째 항과 공비에 0 을 넣었다 |
| 범위의 끝, 등호 | `power-of-a-real-number` 직관 "0 ≤ a < b 이면 aⁿ < bⁿ": n = 0. 고른 연속성 정리의 힌트 "거리가 δ₁/2 미만": 끝점에서는 같다. `echelon-form` 직관 "건너뛴 열이 자유 열": 첫 피벗 앞과 마지막 피벗 뒤의 열도 자유 열. `differentiable-implies-continuous` "같은 빠르기로 작아진다": f′(c) = 0 | 진술의 범위 끝값과 예시의 행렬을 넣었다 |

| 화면 | `subsequence-converging-to-limsup` 의 `\tag`: katex-error 는 없었지만 꼬리표가 식에 붙어 곱으로 읽혔다 | 1000px·390px 스크린숏을 열었다 |

## 7. 기록 형식

지시받은 경로(보통 `<스크래치패드>/reviews/<단원>-self.md`)에 쓴다. 지휘자는 이 기록을 읽고 통과 여부를 판단한다. **"확인했다", "맞다", "문제없음"만 적힌 줄은 확인하지 않은 것으로 본다.** 무엇을 넣었고 무엇이 나왔는지, 무엇을 검색해 어디를 읽었는지가 보여야 한다. 표는 줄여 써도 되지만 줄을 빼지는 않는다.

```
# <단원> 자기 검토
대상 파일: (경로 목록)   초안 사본: <스크래치패드>/draft/
## 1. 진술
- <id> (n): 끝의 경우 <값> → <가정과 결론의 계산>
- (C) <뒤 항목 후보>: 경로 <단계 — 근거 번호> … / 모자란 것: <무엇, 또는 "없음(경로의 모든 단계에 번호가 있다)">
## 2. 출처 표 (블록마다 한 줄)
| 블록 | 대상 | 결론 | 찾은 곳, 또는 검색어(영어·기호·joined)와 읽은 범위 | note 에 적은 말 |
- loc: <id> — <loc> — 줄 <n>, 폼피드 계산 p.<p>.  그림으로 대조한 쪽: …
## 3. 인용 대조
| 인용 | 대상 진술의 요약 | 이 증명이 쓰는 꼴 | 맞음 / 어긋남 → 고친 것 |
- 새로 근거를 단 작은 사실: …
## 4. 일반 문장 표, 가정이 쓰이는 곳 표
## 5. 다시 한 계산 (식과 결과)
## 6. 이름표 검색 (검색어 → 결과)
## 7. 고친 것 (ERROR / WARN / NIT)
- 원래 글: "…" → 고친 글: "…" / 고친 글에 다시 한 확인: …
- 같은 종류를 찾은 검색어와 결과: …
## 8. npm run check, build, 화면 결과
## 9. 끝까지 확신이 없는 곳 (무엇을 해 보았고 왜 확정하지 못했는지)
## 10. 지휘자에게 묻는 것
```

보고(`docs/writing.md` 의 보고 형식)의 "확신이 없는 곳"에는 기록의 9절을 그대로 옮긴다.

## 8. 지휘자에게 넘길 것

혼자 정하지 말고 기록의 10절과 보고에 적는다.

- (C)에서 모자란 진술: 어느 항목의 진술에 무엇을 넣으면 뒤 항목이 쓸 수 있는지 문장으로. 이미 통과한 항목이면 특히.
- 통과한 항목이나 다른 강의와 겹치는 이름표·기호, `docs/conventions.md` 에 올릴 표기·번호.
- 새로 받아들여야 할 사실, 진술을 좁혀야 하는 곳, "아직 없는 도구"에 기대게 된 곳.
- 책을 다 읽지 못해 "출처에 없다"를 확정하지 못한 곳(검색어와 읽은 범위를 함께).
- 상태에 기대는 문장(단원 글, index)이 다른 단원의 진행이나 병합 순서에 따라 거짓이 될 수 있는 곳.
