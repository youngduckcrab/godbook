# 출처 준비 지침

작성에 앞서 출처를 내려받아 읽고, 작성자와 검토자가 쓸 **출처 요약 파일**을 만드는 에이전트(보통 opus)의 작업 설명서다. 사이트의 글은 쓰지 않는다. `content/sources/`에 새 출처를 등록하는 것만 예외다.

출처 요약이 있으면 작성자는 2만 줄짜리 텍스트를 뒤지지 않아도 되고, 지휘자는 범위를 제대로 정할 수 있다. 요약이 틀리면 뒤의 모든 단계가 틀어지므로, 읽지 않은 것은 적지 않는다.

## 먼저 읽을 것

1. 이 문서.
2. `docs/conventions.md` — 특히 "받아들인 사실"과 "아직 없는 도구". 출처의 증명이 이 사이트에 없는 도구에 기대는지 알아봐야 한다.
3. 지시문이 준 단원 계획(다룰 주제나 항목 후보)과, 독자가 이미 배운 단원의 `concepts` 목록.

## 1. 출처를 구한다

- 공개 자료를 우선한다: 저자가 공개한 교재, arXiv, 대학 강의록. `content/sources/`에 이미 있으면 재사용한다.
- 원문을 **스크래치패드**에 내려받는다. 저장소에는 넣지 않는다. 스크립트는 내려받은 파일과 다른 디렉터리에 둔다.
- PDF 는 `pdftotext -layout 원문.pdf 원문.txt`로 텍스트로 바꾼다. 폼피드 문자(`\f`)가 쪽을 나눈다.
- **인쇄 쪽 번호와 PDF 쪽 번호의 대응을 확인한다.** 차례의 쪽수와 본문 쪽 머리글을 두세 곳 대조한다. (Book of Proof: PDF 쪽 = 인쇄 쪽 + 12.)
- 호스트가 막혀 내려받지 못하면 멈추고 지휘자에게 호스트 이름을 보고한다. 네트워크 설정은 지휘자만 바꾼다. 기억으로 대신 채우지 않는다.
- 웹 문서(역사 자료 등)는 태그를 벗긴 텍스트로 저장하고, 저자, 제목, 최종 수정일을 그 문서에서 확인한다.

줄 번호와 인쇄 쪽을 함께 보는 방법:

```bash
awk -v a=6400 -v b=6480 '{n=gsub(/\f/,""); pg+=n} NR>=a && NR<=b && NF {printf "[p%d L%d] %s\n", pg+1-12, NR, substr($0,1,120)}' 원문.txt
```

`pdftotext`의 버릇: 중괄호가 옆줄의 `© ª`로 나온다. 위첨자와 분수가 다른 줄로 밀린다. `∤`가 `-`로, `≠`가 `6=`로 나온다. 수식은 앞뒤 문맥으로 확인한다.

## 2. 새 출처를 등록한다

`templates/source.yaml`을 틀로 `content/sources/<id>.yaml`을 만든다. 저자, 제목, 판, 연도, 출판사, 라이선스는 표지와 판권면에서 본 것만 적는다. 판매 사이트나 검색 결과의 값을 적지 않는다. 쪽수 기준 같은 인용에 필요한 메모를 `note`에 적는다.

## 3. 출처 요약 파일을 쓴다

지시문이 준 경로(스크래치패드)에 단원 하나당 파일 하나를 쓴다. 항목 후보마다 아래를 적는다. **직접 읽은 것만** 적고, 확인하지 못한 것은 "확인 못 함"이라고 적는다.

```
# <단원> 출처 요약
출처 텍스트: <경로>   쪽수 대응: 인쇄 쪽 = PDF 쪽 − N

## <항목 후보 id> | <한국어 이름> | <kind 제안>
- 위치: <절 번호와 제목>, <Definition/Theorem/식 번호>, p.<인쇄 쪽>, 줄 <시작>–<끝>
- 출처의 진술: 수학 내용을 정확히 (가정, 한정 기호, 변수의 범위, 출처의 표기). 핵심 문구는 짧게 원문 인용.
- 출처의 증명: 방법 한두 문장. 증명이 없으면 "증명 없음(연습문제 ○번 / 'easy to verify' 라고만 함)".
- 출처가 증명 없이 넘어가는 곳: (예: "fully reduced" 를 괄호 설명만 붙이고 씀)
- 이 사이트에 없는 도구에 기대는 곳: (docs/conventions.md 의 "아직 없는 도구"와 대조)
- 출처가 든 예와 연습문제: 번호, 쪽, 내용을 한 줄씩. (작성자가 같은 예를 만들지 않도록)
- 출처에 없는 것: 널리 쓰이는 이름이나 용어 가운데 출처에 나오지 않는 것.
- 메모: 쪽 경계, 판에 따른 차이, 출처의 오류로 보이는 것.

## 지휘자에게
- 범위 제안: 이 단원에서 빈틈없이 증명할 수 있는 것 / 받아들이는 사실이 필요한 것 / 미루는 편이 좋은 것과 이유.
- 선행 항목: 지금 사이트에 없어서 먼저 만들어야 하는 정의나 보조정리.
- 읽는 순서 제안.
```

요령:
- 정의·정리 목록은 `grep -n -E "Definition|Theorem|Proposition|Fact|Lemma|Corollary"`로 줄 번호를 뽑은 뒤 앞뒤를 읽는다. 차례만 보고 적지 않는다.
- 정리는 진술만 읽지 말고 증명을 끝까지 읽는다. 어떤 앞선 결과를 인용하는지(번호와 쪽) 적는다. 그 결과가 이 사이트에 없으면 "선행 항목"에 올린다.
- 같은 사실이 책의 다른 곳에서 다시 나오면 그 위치도 적는다. "출처는 ~라고 진술하지 않는다"는 주장은 책 전체를 검색한 뒤에만 적는다.
- 출처가 비형식적으로 다루는 곳("informally", 그림이나 표로만 보임)을 표시한다. 그런 정리는 이 사이트에서 진술을 좁히거나 받아들이는 사실을 명시해야 한다.
- 역사 자료는 쓸 수 있는 문장을 원문 그대로 발췌하고 줄 번호를 붙인다. 날짜, 저작 이름, 평가가 담긴 표현을 구분한다. 번역어 후보도 적는다(transfinite = 초한).

## 4. 보고

요약 파일의 경로, 등록한 출처, 그리고 "지휘자에게" 부분을 답으로 낸다. 확인하지 못한 것을 맨 앞에 적는다.
